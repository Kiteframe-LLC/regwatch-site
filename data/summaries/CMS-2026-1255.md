# Public Summary: CMS-2026-1255-0001

## What This Document Does

**Regulatory Action:** CMS and ONC/HHS propose to extend interoperability and prior authorization rules to drug prior authorization, API endpoint reporting, API usage metrics, FF-SHOP small-group QHP issuers, FHIR-based standards, and related Open Payments audit-access language.

**Affected Entities**
- Medicare Advantage, Medicaid, CHIP, and FFE/FF-SHOP QHP payers
- HIPAA covered entities involved in prior authorization transactions
- health care providers and health IT/API vendors
- patients needing drugs or services subject to prior authorization
- Open Payments manufacturers and group purchasing organizations

**Observed Facts**
- The notice proposes electronic prior authorization for drugs and CMS reporting of API endpoints and usage metrics.
- The notice states that initial economic impact estimates approach the $100 million threshold.

**Inference**
- The rule is mainly an interoperability implementation rule; high-value comments should focus on metric design, endpoint usability, excluded markets, and implementation evidence.

**Evidence Quotes**
- The proposals are intended to improve the electronic exchange of health care data and streamline processes related to prior authorization.
- To help assess the impact of our policies, we are proposing to collect API usage metrics.

## Issues Worth Commenting On (0-6)

- **Id:** registry_governance
  
  **Priority:** high
  
  **Posture:** support with safeguards
  
  **Issue:** Create a reliable CMS API endpoint registry with validation and correction procedures.
  
  **Why It Matters:** Endpoint discovery is only useful if providers and payers can trust the listed endpoints.
  
  **Ask Agency To:** Specify update cadence, validation checks, outage reporting, contact fields, and public correction procedures.
  
  **Supporting Evidence**
  - CMS proposes endpoint reporting for multiple payer APIs.
  
  **Score Drivers**
  - pass5.safeguard_absence
  - pass5.magic_interface_dependency
- **Id:** metrics_that_matter
  
  **Priority:** high
  
  **Posture:** support with improvements
  
  **Issue:** Require API metrics that measure real-world prior authorization performance, not just API traffic.
  
  **Why It Matters:** The rule's benefits depend on whether electronic prior authorization reduces delays, failed exchanges, and administrative burden.
  
  **Ask Agency To:** Add metrics for failed transactions, response times, incomplete data, denial/approval timeliness, manual fallback frequency, and patient access delays.
  
  **Supporting Evidence**
  - CMS proposes collecting API usage metrics to assess policy impact.
  
  **Score Drivers**
  - pass5.magic_interface_dependency
  - pass4.monitoring_and_feedback_design_quality
- **Id:** sbe_evidence
  
  **Priority:** moderate
  
  **Posture:** request explanation
  
  **Issue:** Build a record on whether SBE and SBE-FP exclusions leave similar burdens unresolved.
  
  **Why It Matters:** The same patient and provider prior authorization problems may persist in excluded markets.
  
  **Ask Agency To:** Request burden, API-readiness, and authority evidence for SBE and SBE-FP issuers and identify criteria for future inclusion.
  
  **Supporting Evidence**
  - CMS says it will consider whether future rulemaking should include those issuer types.
  
  **Score Drivers**
  - pass4.distributional_omission_risk
  - pass4.arbitrary_line_drawing_risk
